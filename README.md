# База исполнителей / подрядчиков

Локальный прототип внутренней базы исполнителей для подбора подрядчиков по проектам.

## Состав системы

Система работает в Docker и состоит из двух контейнеров:

- `contractors_db_postgres` — база данных PostgreSQL;
- `contractors_db_web` — Django-приложение.

## Основные функции

- карточки исполнителей;
- несколько специальностей у одного исполнителя;
- справочники специальностей, типов занятости, статусов;
- карточки проектов;
- подбор исполнителей по проекту;
- фиксация суммы КП;
- журнал переговоров;
- комментарии пользователей;
- поиск исполнителей по специальности.

## Запуск проекта

Перейти в папку проекта:

```powershell
cd C:\Projects\contractors_db
```

Запустить контейнеры:

```powershell
docker compose up -d
```

Проверить статус:

```powershell
docker compose ps
```

## Остановка проекта

```powershell
docker compose down
```

## Адреса

Админка Django:

```text
http://localhost:8000/admin/
```

Поиск исполнителей по специальности:

```text
http://localhost:8000/search/
```

## Пользователь администратора

Локальный пользователь создавался командой:

```powershell
docker compose exec web python manage.py createsuperuser
```

Логин и пароль локального администратора хранятся у разработчика прототипа.

## Создание миграций после изменения моделей

```powershell
docker compose exec web python manage.py makemigrations
```

## Применение миграций

```powershell
docker compose exec web python manage.py migrate
```

## Заполнение начальных справочников

Справочники были заполнены через Django shell.

Начальные значения:

### Типы занятости

- Самозанятый
- ИП
- Другое

### Статусы исполнителей

- Активный
- Неактивный
- Черный список

### Типы объектов

- Общественное здание
- Жилое здание
- Промышленное здание

### Статусы подбора

- Рассматривает
- Готов
- Отказ

### Специальности

- АР — Архитектурные решения
- КР — Конструктивные решения
- ОВ — Отопление, вентиляция и кондиционирование
- ВК — Водоснабжение и канализация
- ЭОМ — Электрооборудование и электроосвещение
- СС — Сети связи
- АПС — Автоматическая пожарная сигнализация
- СОУЭ — Система оповещения и управления эвакуацией
- АУПТ — Автоматическая установка пожаротушения
- ПБ — Пожарная безопасность
- ПОС — Проект организации строительства
- СМ — Сметная документация
- ГП — Генеральный план
- ТХ — Технологические решения

## Ручной бэкап базы

Создать папку для бэкапов, если её нет:

```powershell
mkdir backups
```

Выгрузить базу в SQL-файл:

```powershell
docker compose exec db pg_dump -U contractors_user -d contractors > backups\contractors_backup.sql
```

Проверить файл:

```powershell
dir backups
```

## Восстановление базы из бэкапа

Остановить контейнеры:

```powershell
docker compose down
```

Запустить только базу:

```powershell
docker compose up -d db
```

Восстановить базу из файла:

```powershell
Get-Content backups\contractors_backup.sql | docker compose exec -T db psql -U contractors_user -d contractors
```

После восстановления запустить всё приложение:

```powershell
docker compose up -d
```

## Текущая структура данных

Основные модели:

- `Executor` — исполнитель;
- `EmploymentType` — тип занятости;
- `ExecutorStatus` — статус исполнителя;
- `Specialty` — специальность;
- `ExecutorSpecialty` — специальности исполнителя;
- `ExecutorComment` — комментарии к исполнителю;
- `Project` — проект;
- `ObjectType` — тип объекта;
- `ProjectSelection` — подбор исполнителя в проект;
- `SelectionStatus` — статус подбора;
- `SelectionNegotiation` — переговоры по подбору.

## Примечание

Это локальный прототип.

Для размещения на рабочем сервере нужно отдельно настроить:

- постоянное доменное имя или IP-адрес в локальной сети;
- режим `DEBUG=False`;
- отдельные пароли базы данных;
- резервное копирование по расписанию;
- доступ сотрудников;
- при необходимости Nginx или другой веб-сервер.
